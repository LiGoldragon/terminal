# Terminal

Archived terminal harness-control design for Persona.

Status: `terminal` is archived/inactive until further notice. V1 harness work,
including Claude/Codex tests, should use `terminal-cell` directly as the active
terminal primitive. The details below document the prior owner design for
reference.

The crate provided the Persona-facing terminal owner, the ordinary `terminal`
Signal CLI, the `meta-terminal` policy CLI, and local PTY/viewer helpers around
`terminal-cell`. `terminal-cell` owns the low-level PTY and transcript
machinery.

## Where this sits after the Datom migration

`signal-terminal` 2.0.1 and `meta-signal-terminal` 2.0.1 are ethos-declared
contracts: an `ethos/signal.ethos` source, committed generated Rust gated by a
build-time freshness assertion, protos + datom-codec derives, and rkyv frames.
This crate consumes them at those revisions, pinned by immutable rev.

Three things about that consumption are worth knowing before reading the code:

- **`terminal-cell` 2.0.0 now serves the whole `signal-terminal`
  `Query`/`Response` surface itself** — prompt patterns, input gates, write
  injection, worker-lifecycle subscription and session listing. What this
  crate's `contract`, `signal_control` and `supervisor` modules do is
  therefore largely a second implementation of a surface `terminal-cell`
  already owns. That duplication is the substance of the archival, not an
  accident of it.
- **The contract no longer carries this component's observation records.**
  `TerminalSessionObservation`, `TerminalSessionHealthObservation`,
  `TerminalDeliveryAttemptObservation`, `TerminalEventObservation`,
  `TerminalViewerAttachmentObservation` and
  `TerminalSessionArchiveObservation` were dropped when `signal-terminal` was
  rewritten. They are audit rows that never leave this component's own store,
  so they now live in `src/records.rs` as this crate's own types — the
  component that stores them is the component that owns them.
- **There is no envelope layer.** `signal-frame`'s exchange identifiers,
  lanes, sub-replies and subscription tokens are gone from all three
  contracts. One frame is a big-endian `u32` byte count and that many rkyv
  archive bytes (`src/frame.rs`). A streamed event is an ordinary reply frame
  whose value is the contract's own `Response::Event` variant.

## Component CLIs

`terminal <DATOM>` sends one ordinary `signal-terminal::Query` over the
component communication socket (`TERMINAL_SOCKET`, default
`/tmp/terminal.sock`) and prints the typed reply as Datom text.

`meta-terminal <DATOM>` sends one `meta-signal-terminal` query over the
owner-only meta socket (`TERMINAL_META_SOCKET`, default
`/tmp/meta-terminal.sock`) and prints the typed reply as Datom text.

Both take exactly one inline Datom value, as every Datom-speaking CLI does.
The retired `nota-text` feature and the NOTA text form it carried are gone.

## PTY input

`terminal-send <socket> <text>` submits a full prompt by writing text and
Enter. `terminal-type <socket> <text>` writes raw text without Enter, for
tests that need an occupied prompt buffer.

## PTY capture

`terminal-capture <socket>` connects to a durable terminal-cell daemon,
requests scrollback replay, writes the current bytes to stdout, and exits. It
is a debugging and guard substrate for higher layers; it does not interpret
Persona messages.

`terminal-viewer` is the local terminal-cell viewer helper. It is not the
component Signal CLI.

## Named sessions

`terminal-supervisor <terminal-daemon.rkyv>` was the archived engine-facing
component socket during the consolidation. Its process shell is generated by
`schema-rust` from `schema/daemon.schema`: the ordinary communication socket
and terminal meta socket are bound by the shared async task-backed listener
runtime, and the component hook routes external `signal-terminal` /
`meta-signal-terminal` frames into the supervisor actor. The rkyv
configuration carries communication, meta and supervision sockets, socket
modes, store path, and owner identity. It takes exactly one binary
configuration file: inline text names no file and is refused while the
argument is read, and a file that is not a configuration archive is refused at
decode, both before any socket is bound.

`terminal-daemon --store <terminal.sema> --name <terminal>
--control-socket <control.sock> --data-socket <data.sock> -- <command>
[args...]` is the transitional one-PTY terminal-cell witness. It starts a
terminal cell and records the named session (pointing at the control socket)
in the component Sema database after both sockets are bound. The control
socket carries Signal frames and the byte-tag CLI protocol; the data socket
carries the attached-viewer raw byte stream.

`terminal-sessions --store <terminal.sema>` prints the registered sessions.
`terminal-resolve --store <terminal.sema> <terminal>` prints the socket path
for one registered session. These are read-only inspection clients for testing
and operations; effect-bearing input and capture still go through the terminal
socket.

`terminal-viewer --store <terminal.sema> --terminal <terminal>` resolved the
named session, attached to that session's raw data socket, replayed the
terminal transcript, and then streamed live bytes in the archived design.
Closing the viewer did not close the child PTY. `--control-socket <path>
--data-socket <path>` remains available for direct low-level attachment.

`nix run .#test-named-session-registry` starts a named daemon, resolves the
socket through the Sema-backed registry, sends input through the resolved
socket, attaches `terminal-viewer` through the named-session path, and
captures the transcript artifact. It is a stateful host-PTY witness, so it is
exposed as a flake app rather than a pure builder check.

## Signal contract witness

`terminal-signal --control-socket <control.sock> --terminal <terminal> connect`
builds a `signal-terminal` `Query`, round-trips it through a `Signal` frame,
sends it through the Persona terminal transport binding, round-trips the
returned `Response` through a frame, and prints one tab-separated event line.
The round-trips are what the witness exists for: they prove the value the CLI
built survives the archive the wire carries. The event line is this CLI's own
product — `terminal-validate-capture` reads it — not a contract text form; a
contract value's text form is Datom, which the `terminal` CLI prints.

`nix run .#test-terminal-signal` starts a real terminal-cell-backed
`terminal-daemon`, resolves the terminal socket from the Sema-backed registry,
sends a `TerminalInput` query through `terminal-signal`, and captures the
resulting transcript with a `TerminalCapture` query.
